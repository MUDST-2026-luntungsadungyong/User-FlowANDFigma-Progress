## 1. บทนำและวัตถุประสงค์

เอกสารฉบับนี้รวบรวมข้อสรุป กฎทางธุรกิจ (Business Rules) และโซลูชันเชิงวิศวกรรมซอฟต์แวร์ (DevOps & Backend Architecture) เพื่อแก้ไขปัญหาช่องโหว่และกรณีขอบเขต (Edge Cases) ของแพลตฟอร์มซื้อขายการ์ดเกมสะสม (TCG) โดยใช้โมเดล **Escrow Vault (ระบบคนกลาง)** ควบคู่กับ **QC Inspection Hub (ศูนย์ตรวจสอบของแท้และสภาพการ์ด)**

## 2. การแก้ไขปัญหาที่ 1: ระบบนับเวลาอัตโนมัติของสัญญาคนกลาง (SLA Timers)

ในระบบ Escrow จะต้องมี **Background Worker (Cron Jobs)** คอยตรวจจับเวลาเพื่อไม่ให้เงินหรือสินค้าค้างในระบบตลอดไป:

### 2.1 เคสร้านค้าไม่ยอมส่งของเข้า Hub (Ghost Seller Timeout — 48 ชม.)
* **เงื่อนไข:** เมื่อผู้ซื้อชำระเงินเข้า Escrow แล้ว (`Status: PAID`) ร้านค้าจะต้องกดจัดส่ง Leg 1 และระบุเลขพัสดุภายใน **48 ชั่วโมง**
* **การทำงานอัตโนมัติ:**
  - หากครบ 48 ชม. แล้วร้านค้ายังไม่ส่งของ ➔ ระบบจะเปลี่ยนสถานะเป็น `CANCELLED_SELLER_TIMEOUT`
  - ทำการ **Auto-Refund 100%** คืนเงินให้ผู้ซื้อทันที
  - บันทึกประวัติและตัดคะแนนความประพฤติ (Penalty Score) ของร้านค้า

### 2.2 เคสผู้ซื้อได้รับของแล้วไม่ยอมกดยืนยัน (Auto-Release Escrow — 72 ชม.)
* **เงื่อนไข:** เมื่อพัสดุ Leg 2 ส่งถึงมือผู้ซื้อแล้ว (ขนส่งอัปเดตสถานะเป็น `DELIVERED`) ผู้ซื้อมีเวลาตรวจสอบการ์ด **72 ชั่วโมง**
* **การทำงานอัตโนมัติ:**
  - หากพ้น 72 ชม. ผู้ซื้อไม่กดปุ่ม *"ยืนยันรับสินค้า"* และไม่มีการกด *"เปิดข้อพิพาท (Dispute)"*
  - ระบบจะถือว่าผู้ซื้อยอมรับสินค้าสมบูรณ์ (`Status: COMPLETED_AUTO_RELEASE`)
  - ระบบจะทำการ **ปลดล็อกเงินใน Escrow โอนเข้ากระเป๋า Wallet ของผู้ขายทันที**

## 3. การแก้ไขปัญหาที่ 2: การจัดการออเดอร์หลายใบเมื่อมีสินค้าไม่ผ่าน QC (Partial QC Fail)

เมื่อผู้ซื้อสั่งการ์ดหลายใบในออเดอร์เดียวกัน (เช่น การ์ด A 1,000฿, การ์ด B 500฿, การ์ด C 300฿ รวม 1,800฿):

### 3.1 กฎการตัดแยกออเดอร์ (Split & Partial Fulfillment Rule)
* **ผลตรวจ QC ที่ Hub:** การ์ด A (Pass), การ์ด B (Fail / ปลอม / ชำรุด), การ์ด C (Pass)
* **การดำเนินการ:**
  1. **จัดส่งใบที่ผ่าน (Leg 2 Fulfillment):** เจ้าหน้าที่ Hub จะแพ็คเฉพาะ **การ์ด A และ การ์ด C** ส่งต่อไปให้ผู้ซื้อ
  2. **คืนเงินเฉพาะใบที่ตก (Partial Refund):** ระบบจะทำเรื่องคืนเงิน **500 บาท (ค่าการ์ด B)** คืนให้ผู้ซื้อทันที
  3. **จัดการการ์ดที่มีปัญหา:** การ์ด B จะถูกระงับและส่งคืนร้านค้า (Return to Seller) พร้อมบันทึกหลักฐานความผิดของร้านค้า
  4. **การปล่อยเงิน Escrow:** เมื่อผู้ซื้อได้รับพัสดุ Leg 2 ระบบจะโอนเงินเฉพาะค่าการ์ด A และ C (1,300 บาท - ค่าธรรมเนียม) ให้แก่ผู้ขาย

## 4. การแก้ไขปัญหาที่ 3: ระบบล็อคสต็อก 10 นาที และการจัดการคำสั่งซื้อพร้อมกัน

### 4.1 จังหวะการล็อคสต็อก (Locking Phase: Checkout Hold)
* **❌ ไม่ล็อคตอน "Add to Cart":** ป้องกันการโจมตีแบบ *Denial-of-Inventory* (ผู้ใช้/บอทแกล้งกดการ์ดแรร์ใส่ตะกร้าทิ้งไว้เพื่อกันคนอื่นซื้อ)
* **✅ ล็อค 10 นาทีตอน "Proceed to Checkout":**
  - เมื่อผู้ใช้กดปุ่ม *"ดำเนินการชำระเงิน (Proceed to Checkout)"* ระบบจะสร้าง **Distributed Lock ใน Redis (TTL 10 นาที)**
  - แสดงตัวเลขนับถอยหลัง `09:59` บนหน้าจอชำระเงิน
  - หากไม่ชำระเงินภายใน 10 นาที ➔ ระบบจะปล่อยสต็อกคืนทันที เพื่อให้คิวถัดไปมีสิทธิ์สั่งซื้อ

### 4.2 การแย่งชำระเงินในเสี้ยววินาที (Payment Concurrency & Race Condition)
* ในกรณีที่มีผู้ใช้พยายามชำระเงินเข้ามาพร้อมกันในระดับมิลลิวินาที:
  - **เกณฑ์ตัดสิน:** ยึดตาม **Atomic Timestamp ของ Payment Gateway Webhook** (ผู้ที่เงินเข้าถึงระบบก่อนเป็นคนแรกจะได้รับออเดอร์)
  - **การจัดการคนที่สอง:** สำหรับผู้ใช้คนที่สองที่เงินตัดตามหลังมา ระบบตรวจพบว่าสต็อกถูกตัดไปแล้ว ระบบจะสั่ง **Automated Gateway Refund (Reversal)** คืนเงินเข้าบัญชีทันทีภายใน 1 วินาที พร้อมแจ้งเตือนว่า *"สินค้าถูกสั่งซื้อไปก่อนหน้าแล้ว ระบบได้คืนเงินให้คุณเรียบร้อยแล้ว"* โดยไม่ต้องให้ Server รับโหลดการกดซ้ำ

## 5. การแก้ไขปัญหาที่ 4: การกระจายค่าจัดส่ง 2 จังหวะ และหน้ารายงานตำหนิ (4.1)

### 5.1 การกระจายภาระค่าจัดส่ง (Logistics Cost Allocation)
* **รอบที่ 1 (Leg 1: Seller ➔ QC Hub):** **ผู้ขาย (Seller) เป็นผู้รับผิดชอบค่าส่ง** เข้าศูนย์กลาง
* **รอบที่ 2 (Leg 2: QC Hub ➔ Buyer):** **ผู้ซื้อ (Buyer) เป็นผู้รับผิดชอบค่าส่ง** ถึงบ้าน พร้อมชำระ **ค่าบริการตรวจสอบความปลอดภัยและการันตี 100% (Security & Authentication Guarantee Fee)**

### 5.2 ข้อ 4.1: ระบบรายงานตำหนิและให้ผู้ซื้อเลือก (Condition Mismatch Decision Sub-flow)
*(จากการตรวจสอบ: ใน Flow และ Figma เดิมยังไม่มีหน้านี้ จึงต้องเพิ่มเข้าไป)*
* **กระบวนการทำงาน:**
  1. เมื่อเจ้าหน้าที่ Hub ตรวจพบตำหนิที่ร้านค้าไม่ได้ระบุไว้ในรูป ➔ เจ้าหน้าที่จะถ่ายรูป Macro 4K บันทึกเข้าระบบ
  2. ระบบจะส่ง **Push Notification / Email Alert** ไปยังผู้ซื้อ
  3. ผู้ซื้อเปิดหน้าจอ **"รายงานผลตรวจสภาพการ์ด (Condition Mismatch Report)"** เพื่อดูรูปถ่ายตำหนิจริง
  4. ผู้ซื้อมี 2 ตัวเลือกในการตัดสินใจ:
     - **[ ยอมรับสินค้า (Accept as-is) ]:** ยินยอมรับการ์ดสภาพนี้ ➔ Hub ดำเนินการส่งต่อ Leg 2
     - **[ ขอเงินคืนเต็มจำนวน (Reject & Full Refund) ]:** ปฏิเสธไม่รับการ์ด ➔ ระบบคืนเงิน Escrow ให้ผู้ซื้อ 100% ➔ ส่งการ์ดคืนผู้ขาย

## 6. การแก้ไขปัญหาที่ 5: การประกันพัสดุ และความโปร่งใสของ QC Hub (5.1)

### 6.1 ตารางความรับผิดชอบและประกันพัสดุ (Shipping Insurance & Liability Matrix)
เปิดให้ทั้งผู้ซื้อและผู้ขายเลือกชำระ **ค่าประกันพัสดุสูญหาย/เสียหายจากขนส่ง (Opt-in Shipping Insurance)**:

| เหตุการณ์ที่เกิดขึ้น | สภาพการซื้อประกัน | ผู้รับผิดชอบความเสียหาย |
| :--- | :---: | :--- |
| **พัสดุเสียหายจากอุบัติเหตุระหว่างขนส่ง** | ซื้อประกันไว้ ✅ | **แพลตฟอร์ม + บริษัทขนส่ง** ร่วมกันจ่ายค่าสินไหมทดแทน |
| **Seller ส่งการ์ดมา Hub แล้วการ์ดชำรุด** | ไม่ซื้อประกัน ❌ | **Seller รับผิดชอบเองทั้งหมด** (Buyer ได้เงินคืนเต็มจำนวน) |
| **Seller ซื้อประกัน แต่เจตนาหมกเม็ดไม่แจ้งตำหนิเดิม** | ซื้อประกันไว้ ✅ | **Seller รับผิดชอบ** (ประกันไม่คุ้มครองตำหนิที่มีอยู่ก่อนส่ง) |

### 6.2 ข้อ 5.1: ระบบกล้องหลักฐานความโปร่งใสของ Hub (QC Camera Audit Proof)
เพื่อป้องกันไม่ให้ผู้ซื้อหรือผู้ขายกล่าวหาว่าเจ้าหน้าที่ Hub ทำการ์ดเสียหาย:
1. **Unboxing Video Log:** เจ้าหน้าที่ Hub ต้องเปิดกล้องบันทึกวิดีโอตั้งแต่ขั้นตอนเริ่มกรีดเทปแกะกล่องพัสดุของ Seller
2. **High-Res Macro Photos:** ถ่ายรูปสภาพการ์ดความละเอียดสูงทั้ง 4 มุม ด้านหน้าและด้านหลัง ก่อนจะหยิบจับตัวการ์ด
3. **Audit Trail Storage:** อัปโหลดคลิปและรูปภาพขึ้น Cloud Storage (S3) พร้อมประทับเวลา (Timestamp) ผูกกับ `Order ID`
4. **Transparency Portal:** ทั้ง Buyer และ Seller สามารถเปิดดูวิดีโอและรูปถ่ายตอนแกะกล่องได้ตลอดเวลาเพื่อเป็นพยานหลักฐาน

## 7. การแก้ไขปัญหาที่ 6: การป้องกันการฟอกเงินและการถอนเงิน

* **KYC & Bank Name Matching:** บัญชีธนาคารที่ผู้ขายผูกไว้สำหรับถอนเงิน จะต้องมี **"ชื่อ-นามสกุล ตรงกับบัตรประชาชน (National ID)"** ที่ผ่านการยืนยันตัวตน (KYC) แล้วเท่านั้น
* **Withdrawal Holding Period:** เงินจากการขายการ์ดที่มีมูลค่าสูงผิดปกติ จะมีระยะเวลาพักเงินสั้นๆ (Holding Period 24 ชม.) เพื่อป้องกันการฟอกเงินและการแฮกบัญชี

## 8. ตารางสรุปสถานะคำสั่งซื้อ (Order State Machine Matrix)

```
[ CREATED ] ➔ [ PENDING_PAYMENT (10 Min Hold) ] 
     ↓
[ PAID / ESCROW_HELD ] 
     ↓
[ SELLER_SHIPPED_LEG1 (48h Timeout) ] 
     ↓
[ ARRIVED_AT_HUB ] ➔ [ QC_INSPECTION ]
     ├── [ QC_PASS ] ──────────────────➔ [ HUB_DISPATCHED_LEG2 ] ➔ [ DELIVERED ] ➔ [ COMPLETED (72h Auto-Release) ]
     ├── [ QC_MISMATCH ] ➔ [ WAITING_BUYER_DECISION ]
     │        ├── [ BUYER_ACCEPTED ] ─➔ [ HUB_DISPATCHED_LEG2 ]
     │        └── [ BUYER_REJECTED ] ─➔ [ REFUNDED_TO_BUYER ] + [ RETURN_TO_SELLER ]
     └── [ QC_FAIL (Fake/Damaged) ] ──➔ [ REFUNDED_TO_BUYER ] + [ RETURN_TO_SELLER ]
```
